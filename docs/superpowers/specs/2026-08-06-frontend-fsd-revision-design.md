# Ревизия фронтенда: словарь, FSD, линт

Дата: 2026-08-06. Статус: согласовано.

## Зачем

Инвентаризация показала три болезни при в общем-то маленьком фронте
(12 600 строк src, из них 6 100 — shell):

- `App.tsx` — 790 строк и 60 хуков при правиле CLAUDE.md «только композиция
  и состояние сессий»: сессии, клоны, зум, апдейтер, поиск, ресайз,
  конфирмы — всё в одном файле;
- 11 рукописных наборов `hover:bg-fill-…` в шести файлах и 10 голых
  `<button>` мимо словаря; разметка таба продублирована в RepoTabs;
- страница настроек сверстана мимо каркаса приложения (навигация внутри
  карточки, нет ViewBar-шапки).

Токены при этом выдержали: частных значений (`p-[7px]`, `#hex`) — ноль.
Гниёт слой компонентов, а не тема. Лечится словарём, слоями и линтом,
который не даёт откатиться.

## Решения

| Вопрос | Решение |
|---|---|
| Глубина | Полная ревизия фазами: словарь → FSD-переезд с разбором App → ESLint → стражи стилей |
| Слой shared | Не заводим: фундамент остаётся на своих местах, линт классифицирует его рангом 0 по списку путей |
| Слои | корень src (фундамент) → `entities` → `features` → `widgets` → `app` |
| Секции quesk | Не нужны: одна ось (направление), продуктовых silo нет |
| Массовые правки | Запрещены: переносы файлов скриптом `git mv`, импорты правятся по ошибкам tsc |

## Фаза 1 — словарь

Новые части в `src/shell/parts.tsx` (в фазе 2 словарь переезжает в корень
фундамента — `src/parts.tsx`, чтобы виджеты импортировали его вниз, а не
вбок):

- **`Tab`** — таб верхней полосы: иконка, подпись, крестик по ховеру,
  активное состояние. Оба вида табов RepoTabs (репозитории и настройки)
  собираются из него; дубль разметки исчезает.
- **`NavItem`** — кнопка навигации: иконка + необязательная подпись,
  активная — `bg-fill-2 text-foreground`, покой — приглушённый с ховером.
  Использует рейл свёрнутого сайдбара, секции Settings, источники StartPage.
- **`ListRow`** получает двухстрочный вариант (`tall`) для списка коммитов
  FileHistoryView.
- У Button появляется cva-вариант **`field`** (`bg-fill-1 hover:bg-fill-2`) —
  кнопка «в стиле инпута» (сворачивание сайдбара).

Не трогаем: пилюли ViewSwitch и сплит-кнопку Pull — единственные в своём
роде, словарь для повторов.

Settings переверстывается по каркасу: секции слева вне облачка (как левый
сайдбар), контент в карточке с ViewBar-шапкой.

## Фаза 2 — FSD-переезд и разбор App

Физически переезжают только смысловые слайсы; фундамент остаётся в корне
`src` и в `components/ui` (канон shadcn; его знает CLI и design/preview.css),
`generated/` остаётся (путь захардкожен в ts-rs `export_to`), `locales/`
остаётся (его знает i18next).

| Слой | Содержимое |
|---|---|
| фундамент (ранг 0, лежит как лежал) | `components/ui`, `parts`, `icons`, `ipc`, `types`, `generated`, `locales`, `theme`, `prefs`, `i18n`, `toast`, `time`, `paths`, `host`, `resize`, `zoom`, `avatar*`, `vocabulary` |
| `entities/graph` | `scene, render, rows, chips, chipLayout, glyphs, columns, wip, view, refTree` |
| `entities/repo` | `session, repoData, panel` |
| `entities/diff` | `diff, monaco` |
| `features/search` | `search` |
| `features/updater` | `updater` + хук `useReadyUpdate` (выносится из App) |
| `features/menus` | `menuItems, nativeMenu` |
| `features/fileTree` | `fileTree` |
| `widgets/` | все `shell/*.tsx` |
| `app/` | `App.tsx`, `main.tsx` |

Разбор `App.tsx` — часть этой фазы, его хуки и есть будущие features:

- `useReadyUpdate` (опрос + перезапуск) → `features/updater`;
- зум с хоткеями → `useZoom` рядом с `zoom.ts`;
- открытие/клонирование/недавние → `features/openRepo` (`sessionActions`);
- правая панель (ресайз + переключение Details/WorkingTree) →
  `widgets/DetailsPane`;
- репозиторный лейаут (сайдбар + карточка + main + панель) →
  `widgets/Workspace`.

Цель: `App.tsx` ≤ 300 строк — сессии, роутинг главного вида, композиция.
Поведение бит-в-бит: все существующие тесты проходят без правок, кроме
путей импорта. Тесты едут рядом со своими файлами.

Порядок переезда — послойно снизу вверх (entities → features → widgets →
app), каждый слой — отдельный зелёный коммит (tsc + vitest +
boundary:check).

## Фаза 3 — ESLint

Раньше линта не было вовсе. Ставится flat-конфиг:

- `@eslint/js` recommended + `typescript-eslint` recommended +
  `eslint-plugin-react-hooks`;
- своё правило **`fsd/boundaries`** (по образцу quesk, в
  `eslint-rules/fsd-boundaries.js`): ранги фундамент(0) → entity(1) →
  feature(2) → widget(3) → app(4); импортировать можно строго вниз или
  внутри своего слайса; фундамент классифицируется списком путей корня src;
- своё правило **`fsd/public-api`**: между слайсами — только через фасад
  `index.ts` слайса; type-импорты свободны (стираются при компиляции,
  прогон через толстые баррелы рискует циклами типов);
- `npm run lint` встаёт в `build` рядом с `boundary:check`: красный линт
  валит локальную сборку и релиз в CI.

Правила-исходники (`eslint-rules/`) сами не линтуются — это мета-код со
своими конвенциями, как в quesk.

## Фаза 4 — стражи стилей

В `scripts/check-boundary.mjs` (там уже живёт запрет `invoke` вне ipc):

- голый `<button` в `widgets/*` вне `parts` — красная сборка с подсказкой,
  какой частью словаря пользоваться;
- `hover:bg-fill-` в `widgets/*` вне `parts` — красная сборка: стили
  наведения живут только в словаре.

## Тесты

- Части словаря: Tab (клик/крестик/активность), NavItem (активное
  состояние), ListRow tall — обычные vitest-тесты.
- FSD-правила линта: фикстурные файлы с законными и незаконными импортами,
  прогон через RuleTester eslint.
- Стражи стилей: как существующие проверки boundary — скрипт падает на
  подложенном нарушении.
- Весь существующий набор (296 фронтовых, 108 Rust) остаётся зелёным после
  каждой фазы.

## Вне рамок

Секции (silo-ось quesk), физический переезд фундамента, переименование
`components/ui`, дизайн-система в Claude Design, любые изменения поведения.
