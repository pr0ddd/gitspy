# Единый источник состояния репо-операций

Дата: 2026-08-06. Согласовано словами в сессии.

## Задача

Состояние «в репозитории идёт работа» размазано. `useOperations` в
`features/repo/repoActions.ts` держит одно `running` на всё приложение,
а рядом живут четыре независимых островка: `ConflictView.saving`,
`PullPanel.switching`, `HostConnect.busy`, `StartPage.busy`.

Следствия:

- сохранение конфликтов не гасит остальные кнопки репозитория — можно
  запустить операцию поверх записи в рабочее дерево;
- операция в одной вкладке блокирует кнопки во всех, хотя очередь в Rust
  держит по полосе на путь и вкладки друг другу не мешают.

## Решение

Правда живёт во фронтенде. Каждая наша операция начинается с клика во
фронтенде, значит фронтенд уже знает всё, что рассказали бы события из
Rust-очереди; внешние изменения (коммит из терминала) покрыты
`repo:changed`, и очередь про них тоже ничего не знает. Событийная схема
не добавила бы ни одного факта, но потребовала бы затащить в очередь
checkout и сохранение конфликтов.

### Стор

`entities/repo`: `createStore` из `zustand/vanilla`, состояние —
`Map<путь, { kind, target? }>`. Чистый модуль без React, тесты зовут
`getState`/`setState` напрямую. Повторный старт по занятому пути —
ошибка программиста, стор его отвергает: полоса на репозиторий одна,
как и в Rust.

Zustand — новая зависимость. Берётся как канон (как shadcn для
компонентов и sonner для тостов): любое следующее разделяемое состояние
идёт туда же, второго самодельного механизма подписки не заводится.

### Обёртка

`features/repo`: единственная функция `runRepoWork(path, marker, work)` —
помечает репозиторий занятым, выполняет работу, шлёт тост об исходе,
запускает перечитывание, освобождает полосу (в том числе при ошибке).
Через неё идут все мутации репозитория: операции из списка `Operation`,
checkout, коммит, сохранение конфликтов. Тосты репо-мутаций зовёт только
обёртка. Рядом — хук `useRepoWork(path)` через `useStore` с селектором:
виджет подписан на работу своего пути и не рендерится от чужих.

### Занятость по репозиторию

`App.tsx` перестаёт пробрасывать `busy`/`running`/`checkingOut`
пропсами; Toolbar, Sidebar, WorkingTree, PullPanel берут занятость хуком
по пути. Пуш в одной вкладке больше не гасит кнопки в другой.

### Что не трогаем

- Rust и IPC — без изменений.
- Система тостов — без изменений; меняется только то, кто её зовёт.
- `HostConnect`, `StartPage`, апдейтер — у их состояний один
  потребитель, локальный `useState` там правильный масштаб.

## Тесты

- Стор: работы в разных репозиториях независимы; двойной старт в одном
  пути отвергается; завершение с ошибкой освобождает полосу.
- Островок: пока сохраняются конфликты, кнопки репозитория погашены —
  тест обязан падать до починки.
- Существующий тест «ни одного React-рендера при прокрутке» остаётся
  зелёным.

## Объём

Около восьми файлов: стор и обёртка — новые, остальное — механическая
перекладка пропсов на хук в `App.tsx`, `Toolbar.tsx`, `Sidebar.tsx`,
`WorkingTree.tsx`, `PullPanel.tsx`, `ConflictView.tsx`.
