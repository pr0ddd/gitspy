# Интеграции с хостами: подключение, репозитории, клонирование

Дата: 2026-08-02. Область: фаза 8. Хост в этой спеке один — GitHub, но границы
проведены так, чтобы второй хост добавлялся модулем, а не правкой всего подряд.

## 1. Зачем

Клиент git без хоста умеет открыть то, что уже лежит на диске. Всё остальное —
клонировать свой репозиторий, увидеть аватарку автора, позже пулл-реквесты —
требует аккаунта. Это первая часть приложения, которая ходит в сеть, поэтому
она же первой ломает два свойства, которые до сих пор держались сами собой:
приложение работало без сети и не хранило секретов.

## 2. Что сломалось в первой попытке

Записано, потому что план ниже чинит именно это, а не выдуманные недостатки.

### Ожидание жило в промисе фронтенда

`start_connect` отдавал код устройства, а `finish_connect` висел в ожидании
подтверждения и возвращал аккаунт. Пока он висел, любое из событий убивало
подключение молча:

- перезагрузка страницы (правка локали в dev — это `page reload`),
- перезапуск процесса (правка Rust в `tauri dev` — это пересборка),
- закрытие диалога пользователем.

Токен сохранялся в самом конце цепочки, поэтому оборванное ожидание не
оставляло следов. Наблюдаемо это выглядит как «подключаю десятый раз, и всё
без толку»: файла токена на диске нет ни после одной попытки.

### Аккаунт хранился в каждом компоненте свой

`Settings` и `HostRepos` независимо звали `host_account` и держали свой
`useState`. Подключение в диалоге не меняло колонку на стартовой странице:
у неё своя копия, и обновлять её некому. Два состояния об одном факте
расходятся всегда — вопрос только когда.

### Всё жило в `main.rs`

Команды хостов лежали вперемешку с чтением графа, диффом и рабочим деревом,
а их кэши — полями общего `AppState`. Файл рос до тех пор, пока правка в нём
не стала опаснее самой задачи.

### Связка ключей просила разрешение на каждый запуск

Токен лежал в Keychain. У неподписанной сборки, которую `tauri dev`
пересобирает на каждую правку, macOS считает каждую сборку другой программой,
поэтому «всегда разрешать» не запоминается. Плюс код читал секрет по нескольку
раз за запуск — по окну на чтение.

## 3. Принятые решения

### Подтверждение ждёт бэкенд, а не фронтенд

`start_connect` берёт у GitHub код устройства, открывает браузер и **сразу
возвращает код**. Ожидание уходит в фоновую задачу Rust, которая по завершении
пишет токен, сохраняет аккаунт и шлёт событие `host:connected`; при отказе —
`host:failed` с кодом ошибки.

Из этого следует главное: **подключение доводится до конца независимо от
фронтенда**. Перезагрузили страницу — токен всё равно сохранён, а при
следующем чтении аккаунт уже на месте. Закрыли диалог — то же самое.

Повторное нажатие, пока ожидание идёт, не заводит вторую попытку: хост уже
числится подключающимся, и ему возвращается тот же код. Иначе десять нажатий
дают десять живых кодов и десять опросов GitHub.

### Секрет лежит файлом, а не в связке ключей

`~/Library/Application Support/dev.gitspy.app/github.token`, права `0600`.
Так делает `gh`. Расплата названа прямо: файл прочтёт любой процесс под тем же
пользователем, тогда как Keychain этого не позволял. Взамен — ни одного окна
с вопросом, одинаково на всех платформах.

Абстракция `Secrets` остаётся: подключить Keychain обратно — это одна
реализация трейта, а не переписывание команд.

### Ничего не загружается при старте

Аккаунт и список репозиториев лежат на диске в `host-<хост>.json`. Стартовая
страница рисуется из файла, GitHub опрашивается только когда:

- нажали «Подключить»,
- нажали «Обновить»,
- клонируют приватный репозиторий (нужен токен, не список).

Первый запуск после подключения — единственный, когда список тянется из сети
сам.

### Один владелец аккаунта во фронтенде

Аккаунт живёт в `App`. Читается один раз, обновляется по событию
`host:connected`, стирается при отключении. `Settings` и `HostRepos` получают
его свойством и не ходят за ним сами. Компонент, который сам добывает общее
состояние, — это второй источник правды.

### Границы модулей

| Где | Что | Чего не знает |
|---|---|---|
| `crates/gitspy-hosts` | HTTP к GitHub, разбор ответов, хранилище секретов | Tauri, файлы приложения, интерфейс |
| `src-tauri/src/hosts/` | Команды хостов, кэш в памяти, файл `host-*.json`, фоновое ожидание | Граф, дифф, рабочее дерево |
| `src-tauri/src/clone.rs` | Клонирование и создание репозитория | Откуда взялся адрес |
| `src-tauri/src/main.rs` | Сборка приложения и список команд | Как устроена любая из них |

Состояние хостов — своя структура под `manage`, а не поля общего `AppState`.
Клонирование берёт токен через узкую функцию хостов и о GitHub больше ничего
не знает.

### Клонирование считает git, прогресс живой

`git clone --progress`. Stderr читается по мере поступления и режется по
возврату каретки: git пишет прогресс через `\r`, и построчное чтение отдало бы
всё одной строкой в конце, когда прогресс уже не нужен.

Стадии (`Counting`, `Compressing`, `Receiving`, `Resolving`, `Updating`)
сводятся в одну шкалу весами, чтобы полоса не прыгала назад при смене стадии.
Обрывок строки без процента прогрессом не считается — иначе шкала дёргается на
случайные значения.

Токен для приватных репозиториев уходит в git через `credential.helper` и
переменную окружения. В `argv` его класть нельзя: командную строку видит любой
`ps`.

### Что не делаем

- Второй хост (GitLab, Bitbucket). Границы под него готовы, кода нет.
- Пулл-реквесты и аватарки — своя фаза; здесь только аккаунт и список.
- Резюме прерванного подключения после перезапуска процесса: код устройства
  живёт минут пятнадцать, и переживать перезапуск ему незачем. Задача
  прекращается вместе с процессом, пользователь нажимает заново.

## 4. Ошибки

Rust отдаёт код и параметры, фразу собирает фронтенд — общее правило проекта.
Коды хостов: `host.noToken`, `host.badToken`, `host.noApplication`,
`host.denied`, `host.expired`, `host.rateLimited`, `host.network`,
`host.unexpected`, `host.storage`, `host.unknown`. Клонирование добавляет
`clone.exists`, `clone.noDirectory`, создание — `init.taken`.

Отказ на github.com и истёкший код — разные состояния и разные фразы: в первом
случае человек нажал «Cancel», во втором просто не успел.

## 5. Проверяемость

Что можно проверить чистой функцией — проверяется ей: разбор ответов device
flow, разбор списка репозиториев, разбор строк прогресса, веса стадий,
права на файле токена, отказ ключу вида `../../passwd`.

Что нельзя — проверяется против настоящего git: клон кладётся туда, куда
просили; клон в занятую папку падает и чужих файлов не трогает.

Сетевые вызовы в тестах не делаются вообще: клиент разделён на «сходить» и
«разобрать», тестируется второе.
