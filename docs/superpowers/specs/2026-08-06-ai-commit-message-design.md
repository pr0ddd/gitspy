# Генерация сообщения коммита локальной моделью: Ollama и LM Studio

Дата: 2026-08-06. Статус: согласовано.

## Что делаем

Кнопка-искорка рядом с полем Summary в форме коммита, как в GitKraken:
по нажатию staged-дифф уходит локальной модели, и та возвращает заголовок
и описание коммита. Поддерживаются два провайдера — Ollama и LM Studio.
Пользователь провайдера не выбирает: он задаёт адрес сервера, а провайдер
определяется зондом — `/api/version` есть только у Ollama. Ручной выбор
был в первой версии и умер сразу: провайдер «Ollama» с адресом LM Studio
молча работал, потому что оба говорят по `/v1`, и ручка только врала.

## Решения и их причины

**HTTP-клиент живёт в Rust, а не во фронтенде.** Origin у Tauri-webview
не входит в разрешённые у Ollama, CORS зарежет запрос, а лечить это
переменной `OLLAMA_ORIGINS` на машине пользователя — чинить настройку,
которую мы сами и сломали. Из Rust ограничений нет.

**Отдельный крейт `gitspy-ai`, а не модуль в `src-tauri`.** По таблице
слоёв `src-tauri` — границы, а не алгоритмы. Промпт, обрезка диффа и
разбор ответа — предметная логика, ей положен свой крейт с тестами без
Tauri, по образцу `gitspy-hosts`.

**Провайдеры — адаптерами, по правилу `Host`.** Enum
`AiProvider { Ollama, LmStudio }`, весь диспатч внутри крейта,
`if provider == …` снаружи запрещён. Оба провайдера говорят по
OpenAI-совместимому API (`/v1/chat/completions`, `/v1/models`), поэтому
адаптер различается портом по умолчанию (11434 у Ollama, 1234 у
LM Studio) и мелочами формата, но каркас не знает и этого.

**Конфиг живёт во фронтендных prefs, Rust копии не держит.** Каждая
команда получает провайдера, адрес и модель параметрами — ровно как
команды получают `repo`. Единственного «настроенного ИИ» на стороне
Rust не существует по той же причине, по которой не существует
единственного открытого репозитория.

**Дифф — только staged.** Нет застейдженных изменений — кнопка
неактивна с подсказкой. Коммит соберётся из staged, значит сообщение
описывает ровно то, что в него войдёт.

**Ответ приходит целиком, без стриминга.** Ответ просим строгим JSON —
его нельзя показывать по мере печати, а простота разбора важнее
живости: 3–8 секунд ожидания закрывает спиннер на кнопке.

**Промпт фиксированный.** Английский, повелительное наклонение,
заголовок до 72 символов, тело — что изменилось и зачем. Ручек стиля
нет: меньше ручек — меньше способов получить развалившийся ответ.

## Крейт `gitspy-ai`

Зависимости — как у `gitspy-hosts`: `reqwest` (rustls), `serde`,
`serde_json`, `tokio`. Про git и Tauri крейт не знает: дифф приходит
строкой снаружи.

Поверхность:

```rust
pub enum AiProvider { Ollama, LmStudio }

pub async fn list_models(provider: AiProvider, base_url: &str)
    -> Result<Vec<String>, AiError>;

pub async fn generate_commit(
    provider: AiProvider, base_url: &str, model: &str, diff: &str,
) -> Result<CommitDraft, AiError>;

pub struct CommitDraft { pub summary: String, pub description: String }
```

Внутри — три чистых, тестируемых без сети шага и один запрос:

1. **Обрезка диффа** (`trim_diff`): лимит на файл и общий лимит
   (порядок — 4 КБ на файл, 48 КБ всего; точные числа фиксируются
   тестами). Бинарные файлы и lock-файлы (`package-lock.json`,
   `Cargo.lock` и подобные) заменяются строкой-заглушкой с именем
   файла. Если общий лимит превышен, хвостовые файлы сворачиваются до
   заголовка `diff --git` со счётчиком добавленных и удалённых строк —
   модель видит полный список затронутых файлов, но не весь их текст.
2. **Сборка промпта** (`build_prompt`): системное сообщение с правилами
   стиля и требованием ответить строго JSON
   `{"summary": "...", "description": "..."}`, пользовательское — дифф.
3. **Запрос**: `POST {base_url}/v1/chat/completions` с
   `response_format` там, где провайдер его понимает; таймаут на весь
   запрос (120 с — локальная модель на слабой машине думает долго).
4. **Разбор ответа** (`parse_draft`): JSON как есть; JSON в
   код-фенсах; JSON с хвостом болтовни — берём первый разбираемый
   объект. Не разобралось — `AiError::BadResponse` с сырым текстом в
   `detail`.

`list_models` — `GET {base_url}/v1/models`, из ответа берутся `id`.

## Граница: команды Tauri

В `src/ipc.ts` — две функции, в `src-tauri` — две команды:

```
ai_list_models(provider, baseUrl)                  -> string[]
ai_generate_commit(repo, provider, baseUrl, model) -> CommitDraftView
```

`ai_generate_commit` берёт staged-дифф сам: `git diff --cached` через
`gitspy-exec` (обезвреженное окружение уже там). Пустой дифф — ошибка
`ai.nothingStaged`; фронтенд до неё обычно не доводит, потому что
кнопка неактивна, но граница не полагается на дисциплину фронтенда.

Генерация не входит в закрытый список `Operation` и не занимает полосу
операций: она ничего не пишет в репозиторий, и параллельный fetch ей
не мешает.

`CommitDraftView` — в `views.rs` с `#[derive(TS)]`, тип фронтенда
генерируется, как все остальные.

Ошибки — код и параметры, по правилу проекта:

| Код | Когда | Параметры |
|---|---|---|
| `ai.unreachable` | транспорт: не соединились, таймаут | `url`, `detail` |
| `ai.refused` | сервер жив, но ответил не-2xx | `url`, `detail` — статус и `error.message` |
| `ai.modelMissing` | 404 с именем модели: её сняли с сервера | `url`, `model`, `detail` |
| `ai.badServer` | сервер ответил не по протоколу (HTML, чужой JSON) | `url`, `detail` — тело ответа |
| `ai.noModels` | сервер жив, но моделей на нём нет | `url` |
| `ai.badResponse` | модель ответила, но в ответе нет сообщения коммита | `url`, `detail` — сырой текст модели |
| `ai.nothingStaged` | staged-дифф пуст | — |

Не-2xx — это не «не достучались»: раз статус пришёл, сервер жив, и
пользователю называется причина отказа, а не сеть. Сырые технические
строки — серде-ошибки, тела ответов — живут только в `detail`; из
JSON-конверта `{"error":{"message"}}` в подробность идёт сама фраза.
`data: null` в списке моделей — не ошибка разбора, а пустой сервер:
Ollama сериализует пустой список именно так.

## Настройки

Новая секция `ai` в `Settings.tsx`, пятая после `integrations`.
Содержимое:

- **Адрес сервера** — текстовое поле; пустой адрес значит «локальный по
  умолчанию»: проверка пробует `http://localhost:11434`, затем
  `http://localhost:1234`.
- **Кнопка проверки** — зовёт `ai_detect_server`; тот отдаёт провайдера
  и список моделей (embedding-модели отфильтрованы — им нечего сказать
  в коммите). Найденный провайдер называется в подсказке под адресом.
  Пустой список моделей — ошибка `ai.noModels`, а не тихий пустой
  выпадающий список.
- **Модель** — выпадающий список из ответа сервера.

Хранение — `usePref`: `ai.provider` (пишется детектом, не рукой),
`ai.baseUrl`, `ai.model`. Провайдер нужен генерации ради
`response_format`, и его источник — сервер, а не память пользователя.

## Кнопка в форме коммита

В `WorkingTree`, справа в строке поля Summary — иконка-искорка
(`Icon.sparkle`, новая запись в `src/icons.ts`). Состояния:

- **Нет staged-файлов** — неактивна, подсказка «нужны staged-изменения».
- **Модель не настроена** (`ai.model` пуст) — неактивна, подсказка
  ведёт в настройки.
- **Готова** — по нажатию спиннер на месте иконки, повторное нажатие
  недоступно; по ответу оба поля черновика заполняются целиком,
  затирая прежний текст.
- **Ошибка** — тост, поля не трогаются.

Логика — рядом с черновиком, в `features/repo` (хук поверх
`useCommitDraft`), виджет только рисует.

## Тесты

- `gitspy-ai`, без сети: `trim_diff` — лимиты, бинарники, lock-файлы,
  сворачивание хвоста; `parse_draft` — чистый JSON, фенсы, болтовня
  вокруг, мусор; `build_prompt` — дифф попадает в пользовательское
  сообщение, правила — в системное.
- Фронтенд: кнопка неактивна без staged и без модели; заполнение обоих
  полей по ответу; занятость на время запроса; ошибка уходит тостом и
  не трогает поля. По образцу существующих тестов `WorkingTree`.
- Секция настроек: смена провайдера меняет плейсхолдер и сбрасывает
  модель; проверка соединения наполняет список.
