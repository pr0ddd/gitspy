# Клавиатура, выбор и достижимость

## 1. Что не так сейчас

Выбранного файла в приложении нет как состояния. Строка правой панели знает
только про наведение мыши: клик зовёт `onOpen`, тот меняет `main` внутри `App`,
и обратно к строке эта связь не идёт. Поэтому подсветить выбранное нечем —
подсвечивать нечего.

Клавиатура разбросана по пяти местам и нигде не описана: сайдбар и терминал
в `App`, зум в `zoom.ts`, прокрутка графа в `GraphView`, Escape в `ConfirmBar`.
Списка клавиш не существует ни для пользователя, ни в коде.

Половина нажимаемых мест — `div` с `onClick`: строки файлов, строки веток,
вкладки, ручки-разделители. До них не доходит Tab, на них не видно фокуса,
Enter по ним ничего не делает. Мышь обязательна.

Локальная ветка с исчезнувшим upstream помечена красным словом `gone`. Данные
верны — `%(upstream:track)` из `git for-each-ref` отдаёт ровно это, — но у ветки
своя жизнь, и на репозитории с полусотней веток метка стоит у каждой второй
строки. GitKraken на тех же 36 ветках её не рисует.

## 2. Модель выбора

Выбранный элемент — один на приложение, и он всегда виден на экране.

```ts
type Picked = { path: string; staged: boolean };
```

Для файла коммита `staged` не значит ничего и всегда `false`: у списка коммита
одна секция, а два поля вместо одного пути нужны рабочему дереву, где один и тот
же файл бывает сразу в обеих секциях.

Состояние живёт в `App` рядом с `main`, потому что выбор переживает закрытие
диффа: стрелка двигает выбор и тогда, когда в центре граф.

Клик по строке выбирает её и открывает дифф. Переключение (`toggleDiff`)
убирается: оно давало «выбран, но не показан» — состояние, которое подсветка
делает видимой ложью.

Выбор сбрасывается при смене репозитория и при смене выбранного коммита.

Повторное действие ничего не перерисовывает. Открытие уже открытого файла
возвращает прежнее `main` (сравнение через `sameDiffTarget`), выбор той же
строки — прежний `picked` (`samePick`), а выбор того же коммита — прежнее
состояние сессий: `patched` отдаёт тот же объект, когда ни одна сессия не
изменилась. Иначе Enter подряд перестраивал бы панель и дифф на пустом месте.

## 3. Области

Клавиша достаётся той области, где сейчас фокус:

| Область | Что это | Кто её метит |
|---|---|---|
| `files` | список файлов правой панели | `WorkingTree`, `Details` |
| `refs` | список сайдбара | `Sidebar` |
| `graph` | холст истории | `GraphView` |
| `text` | поля ввода, textarea, редактор диффа | сами элементы |

Область читается из DOM: контейнер помечен `data-area`, активная — ближайшая
к `document.activeElement`. Если фокуса нет ни на чём (`body`), берётся область
по виду: открыт дифф — `files`, иначе `graph`. Так стрелки работают сразу после
открытия репозитория, без обязательного клика.

В области `text` работают только аккорды с модификатором: `S` там печатает
букву, а не стейджит файл.

Панель файлов отвечает на «открыть выбранное» и тогда, когда фокус в графе:
стрелка вправо из графа открывает дифф файла — выбранного, а если выбора ещё
нет, первого в списке. Для этого панель регистрирует эту одну команду и без
области.

## 4. Реестр команд

Одно описание на команду, и подпись в справке берётся из него же — иначе
справка станет вторым источником правды и разойдётся с кодом.

```ts
type Chord = { key: string; primary?: boolean; shift?: boolean; alt?: boolean };

type Command = {
  id: CommandId;
  label: string;
  group: 'repo' | 'navigation' | 'ui';
  chords: Chord[];
  area?: Area;
};
```

`primary` — ⌘ на macOS и Ctrl на остальных системах. Платформа определяется
один раз по `navigator.userAgent`; отдельной команды в Rust для этого не
заводится.

Сопоставление события с аккордом и подпись аккорда — чистые функции в
`src/keys.ts`. Реестр и единственный слушатель `keydown` — в
`src/features/keyboard/`. Обработчики подаёт `App` картой по `CommandId`;
команды без обработчика невозможны — это проверяет тип.

### Набор

Заводятся только те команды, за которыми стоит уже существующее действие.

| Группа | Команда | Аккорд |
|---|---|---|
| repo | Commit | ⌘↩ |
| repo | Stage current file | S |
| repo | Unstage current file | U |
| repo | Stage all files | ⌘⇧S |
| repo | Unstage all files | ⌘⇧U |
| repo | Fetch | ⌘L |
| repo | Create branch | ⌘B |
| navigation | Select previous item | ↑, K |
| navigation | Select next item | ↓, J |
| navigation | Open selected | →, ↩ |
| navigation | Close view | ←, Esc |
| navigation | Select first item | Home |
| navigation | Select last item | End |
| ui | Toggle left panel | ⌘\ |
| ui | Toggle terminal panel | ⌘` |
| ui | Search commits | ⌘F |
| ui | Zoom in / out / reset | ⌘+, ⌘-, ⌘0 |
| ui | Close tab | ⌘W |
| ui | Keyboard shortcuts | ⌘/ |

Стеша в списке нет намеренно: ⌘⇧S занят стейджем всего, а выдумывать второй ряд
букв ради полноты таблицы не нужно.

## 5. Списки

Список получает одну точку входа по Tab, внутри водят стрелки. Иначе проход
по сорока веткам стоил бы сорок нажатий Tab.

Разметка: контейнер `role="listbox"` с меткой, строка `role="option"` с
`aria-selected`; `tabIndex` у выбранной строки `0`, у остальных `-1`. Строку
нельзя сделать кнопкой: внутри неё уже есть кнопка Stage, а кнопка внутри
кнопки — недопустимая разметка.

Движение индекса — чистый модуль `src/roving.ts` с тестами. Список листается по
кругу: шаг вниз с последней строки уводит на первую, вверх с первой — на
последнюю. Упор в край заставлял бы отрывать руку от клавиш ради возврата в
начало.

`ListRow` получает `selected` рядом с `current`, и они означают разное:
`selected` — выбор пользователя, даёт фон; `current` — что это HEAD или главное
рабочее дерево, даёт иконку в жёлобе и полужирный текст. Сейчас фон рисует
`current`, и после появления выбора два похожих фона в одном списке читались бы
как одно и то же. Фон остаётся у выбора.

Фокус виден везде, где его раньше не было: строки, вкладки, ручки-разделители,
кнопки переключателя видов. Показывается он тем же, чем наведение мыши, —
подсветкой фона; рамки нет. Правило одно и живёт в `theme.css`: `*` больше не
получает `outline-ring`, а `:focus-visible` гасит браузерный контур и красит фон
интерактивных ролей. Пока фокус рисовался классами по местам, каждое
непокрытое место показывало браузерную синюю рамку — так и вышло с кнопками
панели и переключателем видов сайдбара.

### Действие в строке

Стейдж и анстейдж в строке — знак «+» и «−», а не слово: слово занимало место
пути и читалось тяжелее самой строки. Кнопка проявляется по наведению и всегда
видна у выбранной строки, чтобы клавиатурный путь не отличался от мышиного.
Название действия остаётся в `aria-label`. Кнопка «Stage all» в шапке секции
теряет рамку и становится приглушённой: это не главное действие панели.

Полный путь показывает наша подсказка, а не `title` webview — тот всплывал через
секунду где попало и мимо оформления.

## 6. Следующий файл после стейджа

После стейджа файл уходит из своего списка. Выбор переезжает на следующий в том
же списке; если файл был последним — на предыдущий; если список опустел — на тот
же файл в соседнем списке, куда он только что переехал, чтобы выбор не пропадал
совсем. Дифф идёт за выбором, когда он открыт.

Правило работает по уже отсортированному списку путей, потому что порядок
зависит от вида (`path`/`tree`) и направления сортировки:

```ts
export const pickNext = (paths: readonly string[], removed: string): string | null
```

Чистая функция в `src/entities/repo/`, тесты — на трёх случаях выше.

## 7. Прокрутка графа

`scrollToCenter` центрирует строку, когда та ушла за край. Для стрелок это
неверно: шаг вниз у нижнего края должен доводить холст ровно на строку, а не
прыгать на пол-экрана.

`scrollToReveal` в `scene.ts` уже написан и покрыт тестами, но нигде не вызван —
его и подключаем. Выбор различает шаг и прыжок: сдвиг на одну строку доводит
холст ровно до строки, переход дальше (поиск, переход по ссылке) центрирует, как
и раньше. PageUp и PageDown остаются прокруткой и живут в `GraphView`.

## 8. Окно справки

Диалог shadcn, три группы в порядке реестра, подписи аккордов собираются
`chordLabel` для текущей платформы. Открывается по ⌘/ и кнопкой в нижней панели:
иконка клавиатуры, подсказка вида «Keyboard Shortcuts (⌘ /)». Кнопка и зум стоят
справа, рядом с номером версии.

Фильтра по клавишам нет: команд два десятка, список виден целиком.

## 9. Метка gone

`Tracking` в `Sidebar` перестаёт рисовать `gone`, ключ `sidebar.gone` уходит из
словаря. Поле `gone` в `RefView` остаётся: оно верное, и на нём стоит вопрос об
уборке веток, если он когда-нибудь появится. Ahead и behind остаются как есть.

## 10. Тесты

- `keys.test.ts` — событие с Meta на macOS и с Ctrl на прочих системах даёт одну
  и ту же команду; подпись аккорда различается по платформе.
- `roving.test.ts` — движение, границы, отсутствие заворота.
- `pickNext` — следующий, предыдущий для последнего, `null` для пустого списка.
- `scrollToReveal` — видимая строка не двигает холст; строка за краем доводится
  ровно на строку.
- `WorkingTree.test.tsx` — стрелка двигает подсветку; `S` стейджит выбранный
  файл; после стейджа выбран следующий.
- `Sidebar.test.tsx` — слова `gone` в строке ветки нет.
- Команда из реестра имеет ключ в словаре — полноту и так стережёт
  `i18n:check`, но реестр в него не заглядывает, поэтому проверка отдельная.

## 11. Чего здесь нет

Экранного диктора и озвучивания графа. Настройки «уменьшить движение».
Палитры команд. Уборки веток с исчезнувшим upstream. Ничего из этого не
требовалось, и каждое стоит отдельного разговора.
