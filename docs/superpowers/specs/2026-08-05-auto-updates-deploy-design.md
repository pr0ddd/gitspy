# Автоапдейты и деплой через GitHub Actions и Cloudflare R2

Дата: 2026-08-05. Статус: согласовано.

## Решения

| Вопрос | Решение |
|---|---|
| Триггер релиза | Тег `v*`; пуши в master ничего не деплоят |
| Платформы | Только macOS Apple Silicon (`darwin-aarch64`); схема манифеста готова к добавлению остальных |
| Хранилище | Новый бакет R2 `gitspy-releases`, публичный `r2.dev`-домен |
| Пайплайн | Обычные шаги в workflow (как в quesk `desktop-release.yml`), без стороннего `tauri-action` |
| GH Release | Да: на каждый тег создаётся релиз с dmg для ручной установки |
| UX обновления | Тихо скачать в фоне; кнопка перезапуска в боттом-баре; диалогов нет |

## Релизный workflow

`.github/workflows/release.yml`, job на `macos-14`, `concurrency: release` без отмены.

1. **Страж версии.** Тег, `package.json` и `src-tauri/tauri.conf.json` обязаны нести
   одну и ту же версию, иначе job падает до сборки. Версию наружу показывает
   `__APP_VERSION__` из `package.json` — это единственный источник, остальные два
   файла сверяются с ним.
2. **Кичейн раннера.** Временный кичейн, импорт p12 из секрета
   `APPLE_CERTIFICATE` (base64) с паролем `APPLE_CERTIFICATE_PASSWORD`,
   партишн-лист для codesign.
3. **Сборка.** `npx tauri build`. `beforeBuildCommand` уже гоняет i18n,
   boundary-check, tsc и vitest — красный тест валит релиз. Нотаризация — через
   `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID` (Tauri сам отправляет и ждёт).
   `createUpdaterArtifacts: true` в конфиге даёт `gitspy.app.tar.gz` и `.sig`,
   подписанные ключом из `TAURI_SIGNING_PRIVATE_KEY` (+ его пароль).
4. **Манифест.** `scripts/release-manifest.mjs` собирает `latest.json`:
   `version`, `pub_date`, `platforms.darwin-aarch64.{url,signature}`. URL —
   версионное имя файла на публичном домене бакета.
5. **Выгрузка в R2.** aws cli, эндпоинт `R2_ENDPOINT`, ключи `R2_ACCESS_KEY_ID` /
   `R2_SECRET_ACCESS_KEY`, бакет `R2_BUCKET`. Закон порядка: сначала
   `*.app.tar.gz`, `*.sig` и dmg, `latest.json` — строго последним. Фид никогда
   не указывает на недокачанные файлы.
6. **GH Release.** `gh release create <тег> <dmg>` с автогенерируемыми заметками.

Артефакты лежат под версионными именами (`gitspy_1.0.1_aarch64.app.tar.gz`),
перезаписывается только `latest.json`. Откат — перегенерировать и залить
`latest.json` на прежнюю версию; файлы не удаляются.

## Приложение

- Крейты `tauri-plugin-updater` и `tauri-plugin-process`, права в
  `capabilities/default.json`. В `tauri.conf.json`: endpoint
  `https://<домен бакета>/latest.json`, публичный ключ апдейтера,
  `createUpdaterArtifacts: true`.
- Весь доступ к плагину — в одном модуле `src/updater.ts` (та же дисциплина,
  что `src/ipc.ts`: компоненты плагин напрямую не импортируют).
- Поведение: проверка при старте и каждые 4 часа; найденное обновление
  скачивается сразу и тихо; после скачивания в боттом-баре слева от версии
  появляется кнопка «перезапустить для X» (ключи i18n, никаких диалогов);
  клик — `relaunch()`. Ошибки проверки и скачивания в тосты не идут:
  обновление — фоновая забота, о ней сообщаем только когда оно готово.
- В dev-сборке апдейтер не проверяет ничего (плагин активен только в бандле).

## Ключ апдейтера

`npx tauri signer generate` — единожды. Приватный ключ и его пароль:
секреты GitHub плюс локальная копия вне репозитория. Потеря ключа означает,
что установленные приложения перестанут принимать обновления, — беречь как
сам сертификат. Публичный ключ зашивается в `tauri.conf.json`.

## Секреты GitHub

| Секрет | Откуда |
|---|---|
| `APPLE_CERTIFICATE` | готовый `~/quesk-signing/CSC_LINK.b64.txt` |
| `APPLE_CERTIFICATE_PASSWORD` | `~/quesk-signing/p12-password.txt` |
| `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` | те же, что в кичейн-профиле `gitspy` |
| `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | генерируются на шаге ключа |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ENDPOINT`, `R2_BUCKET` | Cloudflare R2 |

## Ручные шаги в облаках

1. Cloudflare: создать бакет `gitspy-releases`, включить публичный r2.dev-домен,
   выписать API-токен с правом записи в бакет.
2. GitHub: положить секреты таблицы выше.
3. Сохранить копию приватного ключа апдейтера вне репозитория.

## Тесты

- Кнопка обновления: с мокнутым `src/updater.ts` кнопка отсутствует без
  обновления, появляется после «скачано», клик зовёт relaunch — обычный
  vitest-тест боттом-бара.
- Манифест: чистая функция сборки `latest.json` покрыта тестом (правильные
  поля, версия без префикса `v`, URL с версионным именем).
- Страж версии: скрипт сверки версий покрыт тестом на расхождение.
- Порядок выгрузки тестом не ловится — он закреплён порядком шагов workflow и
  комментарием-предупреждением в нём не нуждается: шаги названы
  `Upload artifacts` и `Publish manifest last`.

## Вне рамок

Windows/Linux/Intel-сборки, свой домен вместо r2.dev, дельта-обновления,
канал beta — всё добавляется поверх этой схемы без её переделки.
