# Пулл-реквесты: чтение и переход на ветку

Дата: 2026-08-03. Объём согласован: список, детали, один переход — checkout
ветки PR. Ревью, комментирование и статусы CI — следующие вехи. Эталон вида —
GitKraken (скриншот в переписке от 2026-08-03).

## 1. Зачем и что именно

PR в git-клиенте нужен для одного главного жеста: увидел — перешёл на ветку —
смотришь код у себя. Всё остальное (описание, комментарии, метки) — контекст,
чтобы не открывать браузер. Поэтому вехой правит кнопка «перейти на ветку»,
а не полнота карточки.

## 2. Узкие места, продуманные заранее

### Откуда берётся owner/repo

PR принадлежат репозиторию на GitHub, а у нас есть только путь на диске и
список remote. Отображение `remote URL → owner/repo` — чистая функция в
`gitspy-hosts`, разбирающая три формы адреса:

- `https://github.com/owner/repo.git`
- `git@github.com:owner/repo.git`
- `ssh://git@github.com/owner/repo`

Берётся `origin`, если он указывает на GitHub; иначе первый remote с адресом
GitHub; иначе секция честно говорит «этот репозиторий не на GitHub».
Функция тестируется на всех трёх формах и на чужих хостах.

### Ни одного сетевого вызова при открытии — правило остаётся

Список PR живёт на диске: `pulls/github/{owner}--{repo}.json` в каталоге
данных, с временем получения. Открытие репозитория рисует секцию из кэша и
в сеть не ходит — это проверяемое свойство, не обещание.

Кэш читается сразу при открытии репозитория — это диск, а не сеть. Сеть
трогается ровно в двух случаях, и оба — явный жест человека:

1. раскрытие секции PR: кэш виден мгновенно, список обновляется фоном
   (отдельной кнопки обновления нет — раскрытие и есть просьба показать);
2. открытие карточки PR (детали и комментарии всегда свежие).

### Группы без лишних запросов

«Мои», «Назначенные», «Ждут моего ревью» — это фильтры по уже полученному
списку: автор — я, в assignees — я, в requested_reviewers — я. Логин берётся
из подключённого аккаунта. Ни одного дополнительного запроса; группировка —
чистая функция с тестами.

### Переход на ветку — два случая, и они разные

| Откуда PR | Что делаем |
|---|---|
| ветка этого же репозитория | `fetch origin` + `checkout <branch>` — настоящая ветка, с неё можно пушить |
| форк | `fetch origin +pull/{n}/head:refs/heads/pr/{n}` + `checkout pr/{n}` — локальная копия, пуш обратно в форк не обещаем |

Различаются по `head.repo.full_name == base.repo.full_name`. Обе — две команды
git подряд под одной полосой очереди операций; вторая не начинается, если
первая упала. Токен уходит тем же способом, что у fetch/pull/push.

### Сколько тянем

Список — открытые PR, страницами по 100, потолок пять страниц. Если PR больше,
секция пишет «показаны первые 500» — молчаливое усечение запрещено. Детали и
комментарии — по одному запросу на открытие карточки, в память (не на диск):
это самая изменчивая часть, кэшировать её на диск значит показывать вчерашние
комментарии как сегодняшние.

### Маркдаун

Описание и комментарии — GitHub-маркдаун: заголовки, списки с чекбоксами,
код. Без отрисовки это нечитаемо, значит нужен рендер: `react-markdown` +
`remark-gfm`. GitHub-маркдаун опирается и на HTML — `<details>`, `<img>`,
скрытые комментарии `<!-- -->`, — поэтому сырой HTML разбирается
(`rehype-raw`) и просеивается гитхабовским списком разрешённого
(`rehype-sanitize`): комментарии исчезают, свёртки работают, скрипты и
обработчики не проходят. Оформление — утилиты Tailwind на токенах, никаких
своих css-файлов.

## 3. Слои

| Где | Что добавляется |
|---|---|
| `crates/gitspy-hosts` | `pulls.rs`: разбор списка, деталей, комментариев; `remote.rs`: owner/repo из адреса; запросы в `GitHub` |
| `src-tauri/src/hosts/` | команды `pull_requests`, `pull_detail`, дисковый кэш списка |
| `src-tauri/src/operations.rs` | `FetchPull { number }` в закрытом списке; `checkout_pull` гоняет пару команд через полосу |
| `src` | секция в сайдбаре с группами, вью PR вместо графа (по образцу диффа), маркдаун |

Центральное вью перестаёт быть парой «граф или дифф» и становится
перечислением: граф, дифф, PR. Это уже назревшее исправление: два булевых
флага на три состояния — источник невозможных комбинаций.

## 4. Ошибки

Коды по правилу проекта: `host.notGitHub` (нет remote на GitHub),
`pull.gone` (PR закрыт или удалён между списком и карточкой) — плюс уже
существующие `host.*`. Отказ checkout при грязном дереве — это `exec.failed`
с честным stderr от git, ничего не выдумываем.

## 5. Готовность

- Открытие репозитория не делает сетевых вызовов — секция рисуется из кэша.
- Список раскладывается по четырём группам без единого лишнего запроса.
- Карточка показывает описание маркдауном, метки, ревьюеров, комментарии.
- «Перейти на ветку» работает и для ветки репозитория, и для форка;
  занятое имя ветки не роняет, а переключает.
- Больше 500 открытых PR — честная подпись об усечении.
