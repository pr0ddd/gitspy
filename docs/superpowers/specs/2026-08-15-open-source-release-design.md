# Выход в открытый код: история, лицензия, платформы, чистка

Дата: 2026-08-15. Статус: на согласовании.

## Решения, принятые заказчиком

- Мостовой релиз не нужен: пользователей двое, канал обновлений переезжает на
  GitHub Releases сразу; R2 выключается.
- Лицензия — **AGPL-3.0-only**. Пул-реквесты принимаются свободно: AGPL
  ограничивает закрытые форки и сервисы, а не вклад.
- Электронная эра из истории исчезает целиком; всё, что после перехода на
  Rust, остаётся.
- `docs/` удаляется полностью. В репозитории не остаётся ни одной строки
  по-русски: ни в тестах, ни в сообщениях `assert`, ни в скриптах, ни в
  `CLAUDE.md`.
- Сборки под macOS (arm64, x86_64), Linux (x86_64), Windows (x86_64) в одном
  прогоне; ручную проверку на каждой платформе делает заказчик.
- README и всё оформление репозитория — на исполнителе; скриншоты даёт
  заказчик. Репозиторий открывает заказчик сам.

## Порядок работ и почему такой

Часть шагов необратима (переписывание истории, публикация), часть меняет
хеши коммитов (и, значит, теги). Порядок:

1. Секреты: перевыпуск и сканирование текущего состояния.
2. Чистка: файлы, `.gitignore`, `docs/`, русский текст, кодовые хаки, раскладка.
3. Лицензия.
4. Переписывание истории → сразу повторное сканирование секретов.
5. CI на PR + матрица платформ + релиз на GitHub Releases + updater.
6. Ручная проверка на трёх ОС.
7. README, CONTRIBUTING, шаблоны, CODEOWNERS.
8. Релиз 1.1.0 из чистой истории; открытие.

Секреты — первым пунктом, потому что ключи из истории надо **перевыпустить
на стороне провайдеров независимо** от того, вычистим ли мы их из git:
переписанная история не отменяет того, что значения уже побывали в
удалённом репозитории.

## 1. Секреты

**Что найдено.** Коммиты `5b359f7`, `50d122b` (2025-09-23) содержат `.env`
с настоящими `GITHUB_OAUTH_CLIENT_SECRET` и `BITBUCKET_OAUTH_CLIENT_SECRET`;
`92f0361` снял файл с отслеживания. Из `master` и из любой ветки, включая
удалённые, эти коммиты **не достижимы** — их держат только локальные
`refs/original/*` (остаток прошлого `filter-branch`) и `refs/stash`. Но
`refs/original/refs/remotes/origin/master` указывает на них — значит, до
переписывания они побывали на GitHub. Секреты считаются скомпрометированными.
Файл `.env` до сих пор живёт в рабочем каталоге, не отслеживается,
`.gitignore` его закрывает.
Client id хостингов зашиты в код (`gitspy-hosts/src/{github,gitlab,bitbucket}.rs`)
— это нормально: client id публичен, обмен кода на токен идёт через PKCE
либо через наш Cloudflare-воркер (`workers/oauth-relay`), где и должен жить
секрет.

**Делаем.**

- Перевыпустить client secret у GitHub OAuth App и у Bitbucket consumer.
  Старые — отозвать. Новые положить только в секреты воркера (wrangler
  secret), нигде в репозитории.
- Убедиться, что приложение не читает `.env` вообще (сейчас `.env`
  описывает переменные, которых нет в коде — проверить `grep` по
  `GITHUB_OAUTH`, `BITBUCKET_OAUTH` в `crates/`, `src-tauri/`, `src/`; всё
  лишнее удалить). Файл `.env` из рабочего каталога удалить, оставить
  `.env.example` только если воркеру нужен — иначе не оставлять ничего.
- Ключ подписи updater'а (`pubkey` в `tauri.conf.json`) — публичный,
  остаётся. Приватный лежит в секретах GitHub Actions
  (`TAURI_SIGNING_PRIVATE_KEY`, `..._PASSWORD`) — проверить, что нигде
  больше. Менять его нельзя: копии 1.0.x откажутся ставить обновление,
  подписанное другим ключом. Заказчик решил, что это не важно, но менять
  всё равно незачем.
- Apple: сертификат, пароль, Apple ID, team id — только в секретах CI.
- Сканирование истории двумя разными инструментами до и после
  переписывания: `gitleaks detect --source . --log-opts="--all"` и
  `trufflehog git file://. --only-verified` (verified-режим проверяет
  найденные значения против провайдеров — ловит живые ключи). Плюс ручной
  `git log --all -p -S` по подстрокам известных секретов из старого `.env`.
  Критерий готовности: оба сканера молчат на переписанной истории, ручной
  поиск по значениям — ноль совпадений.

там, где `CLAUDE.md` и велит им жить.

## 3. Лицензия

- `LICENSE` — полный текст AGPL-3.0-only в корне.
- `license = "AGPL-3.0-only"` во всех `Cargo.toml` (корневой workspace и
  6 крейтов + `src-tauri`), `"license": "AGPL-3.0-only"` в `package.json`,
  `workers/oauth-relay/package.json` если появится.
- Проверка зависимостей: `cargo deny check licenses` с политикой
  «разрешены MIT, Apache-2.0, BSD-*, ISC, MPL-2.0, Unicode, Zlib; запрещены
  GPL-несовместимые проприетарные»; для npm — `license-checker --production
  --failOn 'UNLICENSED;...'`. AGPL совместима с копилефтом GPL, так что

- Заголовки лицензии в каждом файле не ставим: AGPL этого не требует,
  `LICENSE` в корне достаточно; шапки в 400 файлах — шум.

## 4. История

**Что убираем.** 130 коммитов от `3dcf869 Initial commit` (2025-08-26) до
`67948f9` включительно — Electron-эра. **Что оставляем.** 283 коммита от
`da3ba7a feat: минимальное приложение — выбор репозитория и граф`
(2026-08-02) до текущего `master` — как есть, с сообщениями и датами.

**Простыми словами, что произойдёт.** История — цепочка коммитов, каждый
знает своего родителя. Мы говорим git: «считай, что у `da3ba7a` родителей
нет», и пересобираем цепочку от него до сегодняшнего дня. Содержимое всех
283 коммитов не меняется ни на байт, но их хеши станут другими (хеш
включает родителя). Всё, что было до, перестаёт быть достижимо и после
`git gc` физически исчезает из репозитория. На GitHub надо будет
перезалить ветку `master` принудительно, а старые ветки и теги удалить —
иначе они удержат старые коммиты живыми.

**Механика.**

1. Свежий клон в отдельный каталог: `git clone --mirror` — работаем на
   копии, оригинал не трогаем до проверки.
2. Сначала снести всё, что не `master`: 13 локальных веток-черновиков,
   `refs/original/*`, `refs/stash` — иначе `--mirror` утащит их в
   публичный репозиторий, а `refs/original` ещё и держит коммиты с
   секретами. Проверено: единственный корень `master` — `3dcf869`, и
   `da3ba7a` — его линейный предок; коммиты с `.env` из `master` не
   достижимы. После чистки refs — `git replace --graft da3ba7a` (без
   родителей) → `git filter-repo --force`. Дополнительно
   `--path .env --invert-paths` — страховка на случай, если `.env`
   всплывёт где-то ещё; на `master` его нет, шаг обязан оказаться пустым.
3. `docs/`, `bogus.png`, `real.png`, `hello.txt` — тоже `--invert-paths`,
   чтобы их не было даже в истории; иначе «удалить полностью» не выполнено.
4. Проверка: `git log --all --oneline | wc -l` ≈ 280, `git log --all --
   .env` пуст, оба сканера секретов молчат, `git fsck` чист, сборка и все
   тесты зелёные на переписанной копии.
5. Теги `v1.0.0`…`v1.0.6` перевешиваются на новые хеши тем же
   filter-repo автоматически (он переписывает и теги); теги Electron-эры
   (`v0.0.2`, `v0.0.3`) удаляются вместе с историей.
6. Публикация: на GitHub сейчас 9 веток (`Loader-state`, `Quiet-design1`,
   `avatars`, `branches`, `merges`, `patch-view`, `quiet-design`,
   `resize-columns`, `master`) — удалить все, кроме `master`, удалить
   релизы `v0.0.x`, затем `git push --force --mirror`. GitHub держит
   недостижимые объекты ещё некоторое время (и в кэшах PR/форков) —
   после пуша написать в поддержку GitHub с просьбой запустить gc по
   репозиторию, это штатная процедура для утечек. Локальный клон
   заказчика переклонировать заново.
7. Про Electron не остаётся ни строки: проверить `grep -ri electron` по
   дереву и `CHANGELOG.md` (в 1.0.0 сейчас есть фраза «rebuilt from scratch
   after the Electron prototype was thrown away» — оставить или убрать —
   решение заказчика; спека предлагает убрать, раз цель «чтобы никто не
   видел»).

**Риск.** После открытия репозитория переписывать историю нельзя: чужие
форки удержат старое. Поэтому §4 строго до §8.

## 5. CI, платформы, релиз, обновления

### 5.1 CI на pull request

Новый `.github/workflows/ci.yml` на `pull_request` и `push` в `master`:
те же ворота, что сейчас гоняет релиз (`cargo fmt --check`, `clippy
--all-targets -D warnings`, `cargo test --all-targets`, `npm run
i18n:check`, `boundary:check`, `tsc`, `vitest`), плюс `cargo deny` и
`license-checker`. Матрица ОС для Rust-тестов — три ОС (уже дважды ловили
«на маке проходит, на linux нет»). Без зелёного CI пул-реквест не
принимается — включить branch protection на `master`.

### 5.2 Релиз

`release.yml` перестраивается:

- Матрица `build`: `macos-14` (aarch64-apple-darwin), `macos-13`
  (x86_64-apple-darwin), `ubuntu-22.04` (x86_64-unknown-linux-gnu; AppImage
  + deb), `windows-latest` (x86_64-pc-windows-msvc; nsis + msi).
- Подпись/нотаризация — только маки. Windows без сертификата на старте:
  SmartScreen предупредит, это назвать в README. Linux — без подписи.
- Артефакты собираются одной задачей `publish` после матрицы:
  `latest.json` updater'а с секциями `darwin-aarch64`, `darwin-x86_64`,
  `linux-x86_64`, `windows-x86_64` (`scripts/release-manifest.mjs`
  переписывается под несколько платформ; сейчас знает про одну).
- Публикация — только GitHub Release: `softprops/action-gh-release` с
  бинарями, `.sig`-файлами и `latest.json`; текст релиза — из
  `CHANGELOG.md` через `release-notes.mjs` (как сейчас).
- Из workflow уходят все шаги R2, переменная `UPDATES_BASE_URL`, секреты
  `R2_*` удаляются из настроек репозитория.

### 5.3 Updater

`tauri.conf.json` → `plugins.updater.endpoints`:
`https://github.com/pr0ddd/gitspy/releases/latest/download/latest.json`.
Ключ подписи прежний. Копии 1.0.x, которые ходят на R2, обновлений
больше не увидят — заказчик это принял.

### 5.4 Терминал на других ОС

`gitspy-term` уже спавнит `$SHELL` (или `/bin/sh`), zsh-интеграция только
для zsh. На Windows `$SHELL` нет — нужен `COMSPEC`/PowerShell; на этом
этапе терминал на Windows либо PowerShell без интеграции, либо честно
отключён с подписью. Решение — при ручной проверке заказчиком (§6).

## 6. Ручная проверка

Заказчик прогоняет собранные из CI артефакты на macOS, Linux, Windows:
открытие репозитория, граф, дифф, стейдж, коммит, пуш через OAuth,
терминал, обновление с предыдущей сборки. Список — чек-лист в
`docs`-заменителе: `.github/RELEASE_CHECKLIST.md`.

## 7. Оформление репозитория

- `README.md` (англ.): одна фраза о том, что это; главный скриншот; три
  фичи, которых нет у других (граф на canvas без React-рендеров при
  прокрутке; hunk-режим со стейджем по частям; терминал в окне);
  установка на трёх ОС; «собрать из исходников» (Rust stable ≥ 1.85, Node
  22, системный git); архитектура в трёх абзацах — таблица слоёв из
  `CLAUDE.md`; правило владения gix vs системный git с числами; лицензия.
- `CONTRIBUTING.md`: команды проверки, правило «без комментариев в коде»
  с объяснением куда девать «почему», коммиты по-английски и с числами,
  тесты против настоящего git, FSD и `parts.tsx`, i18n-ключи вместо строк.
  Это то, что сегодня в `CLAUDE.md`, переведённое и обращённое к человеку
  снаружи. `CLAUDE.md` остаётся, тоже на английском, и ссылается на
  `CONTRIBUTING.md`, а не дублирует его.
- `SECURITY.md`: куда сообщать об уязвимости (email заказчика), что
  приложение запускает системный git с обезвреженным окружением, где
  хранит токены хостингов.
- `.github/ISSUE_TEMPLATE/bug.yml`, `feature.yml`, `PULL_REQUEST_TEMPLATE.md`
  (чек-лист: тесты, `npm run build`, без русского, ченджлог в
  `Unreleased`), `CODEOWNERS` = заказчик, `dependabot.yml` для cargo и
  npm (еженедельно, группами).
- Ветки на GitHub: только `master`; branch protection: PR обязателен,
  зелёный CI обязателен, линейная история.

## 8. Релиз и открытие

Из переписанной истории режется `v1.1.0` (минорная: новый канал
обновлений, три платформы, лицензия — это уже другое соглашение с
пользователем). После зелёного релиза заказчик переключает репозиторий в
public.

## Что не делаем

- Не ставим лицензионные шапки в файлы.
- Не переводим `CHANGELOG.md` задним числом сверх удаления упоминания
  Electron — он уже по-английски.
- Не меняем ключ подписи updater'а.
- Не трогаем FSD-раскладку и структуру крейтов.

## Проверка готовности

- `git log --all -- .env` пуст; сканеры молчат; ключи провайдеров
  перевыпущены.
- `grep -rlP "[А-Яа-яЁё]" .` по дереву (кроме `node_modules`, `target`,
  `src/locales`) — пусто.
- `ls` корня: только манифесты, конфиги, `LICENSE`, `README.md`,
  `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `CLAUDE.md`, каталоги
  `crates/ src/ src-tauri/ design/ workers/ scripts/ eslint-rules/ .github/`.
- CI зелёный на PR из форка (проверить форком с другого аккаунта).
- Релиз `v1.1.0` выложил четыре сборки и `latest.json`; приложение с
  `v1.1.0` видит `latest.json` и не предлагает обновление само себе.
