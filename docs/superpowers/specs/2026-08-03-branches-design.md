# Ветки: скачивание, переключение, стрелки

**Дата:** 2026-08-03
**Основание:** разбор логов GitKraken на машине заказчика, замеры `git for-each-ref`
на `~/projects/react` (35 074 коммита, 1 118 ссылок), чтение текущего кода.

Задача: локальные и удалённые ветки в сайдбаре деревом папок, переход по двойному
щелчку, создание локальной из удалённой, стрелки «впереди / позади», и то, что
делает цифры в этих стрелках живыми.

---

## 1. Откуда взяты решения

Заказчик просил повторить поведение GitKraken. Вместо пересказа по памяти —
разбор его журналов в `~/.gitkraken/logs/repos/`, 52 файла. GitKraken пишет туда
каждую операцию с меткой времени, началом и концом. Это чёрный ящик, наблюдаемый
снаружи: поведение, а не код.

Первые два утверждения, которые я сделал по памяти, разбор опроверг или уточнил.
Поэтому здесь записаны улики, а не выводы.

### Пула при переключении нет

**109 переключений, `Pull` следом за семью.** Задержки между концом переключения
и началом пула: 0.89, 1.66, 1.69, 2.55, 3.44, 4.75, 6.62 с. Такой разброс даёт
рука, а не таймер. `Pull` в журналах встречается после чего угодно — после
`Push`, после `Unstage`, после ничего.

Предположение заказчика «при переключении делает пул» описывало верный симптом:
чужой коммит действительно появляется сам. Причина другая.

### Фоновый фетч есть, и его период — минута

Фоновый фетч **не пишет в журнал ни `started`, ни `finished`** — только провалы.
Отсюда 560 строк `Fetch remote origin: fatal` против 38 `started`. Это и есть
способ его измерить.

Промежутки между быстрыми отказами (`Could not resolve host`, без растягивающего
картину таймаута DNS):

| минут | сколько раз |
|---|---|
| **1** | **20** |
| 2 | 2 |
| 8 | 2 |
| 10 | 2 |
| 17 | 3 |
| 61 | 5 |
| 83 | 2 |
| 87 | 3 |

Минута доминирует; часовые промежутки — время, когда приложение было закрыто.
1 ноября таких попыток семь за день, и между ними в журнале **вообще ничего** —
ни одной операции человека.

### Переход на удалённую ветку — это DWIM

Журнал пишет `Checkout refs/remotes/origin/X` и **не пишет** `Create ref
refs/heads/X`. Но локальная ветка после этого есть, и это видно по следам:

- после `Checkout refs/remotes/origin/master` идёт `Pull master`, а не
  `Pull origin/master` — пул работает по локальной ветке;
- после `Checkout refs/remotes/origin/builds/facebook-fbsource` через четыре
  минуты идёт `Checkout refs/heads/builds/facebook-fbsource` — локальная уже
  существует.

Значит журнал называет **то, на что нажал человек**, а делается обычный DWIM
`git switch X`: локальная ветка того же короткого имени создаётся с отслеживанием
удалённой, а если уже есть — просто переход на неё.

Это опровергает первую редакцию проекта, где стояло безусловное
`checkout -b X --track origin/X`: на существующей локальной ветке такая команда
падает.

### Автостеш — принадлежность пула, не переключения

`Auto-stash uncommitted changes` встречается 20 раз, и всегда в одной обёртке:

```
Fetch remote origin
Merge origin/main into main: started
  Auto-stash uncommitted changes
  Stage N files for stash
Merge ... finished
Pop most recent stash
```

Вокруг `Checkout` его нет ни разу. Переключение при грязном дереве у GitKraken
просто не удаётся, и он показывает тост: «Checkout Failed. 1 conflict prevents
checkout. Commit, stash, or discard your changes first».

**Решение заказчика:** делаем так же — честный отказ тостом. Молча стешить нельзя:
работа уезжает туда, где её потом ищут.

## 2. Ссылка узнаёт про upstream

`RefLabel` сегодня — `{ name, kind, commit, is_head }`. Отслеживания в нём нет
вовсе, поэтому стрелки сейчас есть ровно у текущей ветки и приходят отдельным
путём, из `git status`.

Добавляются `upstream: Option<String>`, `ahead: u32`, `behind: u32`, `gone: bool`.

### Источник — git, а не свой обход

```
git for-each-ref --format='%(refname:short)%09%(upstream:short)%09%(upstream:track,nobracket)'
```

Формат проверен на фикстуре: `main|origin/main|ahead 2, behind 1`, без
отслеживания — пусто, у потерянного upstream — `gone`.

**Замер: 10 мс на 1 118 ссылок react, один процесс.** Повторено трижды.

Своего обхода графа не пишем по той же причине, по которой не считаем дифф:
`branch.<name>.merge`, правила разрешения upstream, `[gone]`, поведение при двух
remote с одинаковым именем — это знает git. Разойтись с тем, что человек видит в
терминале, мы позволить себе не можем, а в тестах такое расхождение не ловится:
оба ответа выглядят правдоподобно.

### Где это живёт

`crates/gitspy-exec/src/tracking.rs`, рядом со `status.rs`, который уже разбирает
`branch.ab` из `git status --porcelain=v2` тем же способом.

**Побочно: таблица слоёв в `CLAUDE.md` врёт.** Она называет `gitspy-exec`
«Запись», а он уже делает и чтение — то, которое умеет только git. Правится
описание, а не код: строка становится «Запуск системного git: запись и то чтение,
на которое отвечает только git».

## 3. Дерево ссылок

Имя ветки режется по `/`. `pr/36451` → папка `pr`, лист `36451`. У удалённых
первый сегмент — имя remote, оно уже часть имени в `RefView`.

Правила сняты со скриншотов GitKraken:

- **цепочки не схлопываются**: `fixtures › packaging › brunch › dev ›
  minimatch-3.1.5` — пять строк с нарастающим отступом, а не одна склеенная;
- **папки и листья в общем алфавитном порядке**, папки наверх не всплывают:
  `ci` (папка), `develop` (лист), `feat` (папка);
- фильтр раскрывает ветви, где есть совпадение, и сравнивает с полным именем.

Чистая часть — `src/refTree.ts`: плоский список ссылок → дерево. Ни одного
обращения к React, покрыта тестами: форма дерева, порядок, раскрытие под фильтром,
имя с завершающим или двойным слэшем.

## 4. Строка ветки

```
[✓]   ⌐ 36451                                    70↑
 ▲     ▲                                          ▲
 текущая  отступ по глубине          впереди / позади, потолок 99+
```

- **Текущая ветка** — зелёная галка слева и зелёная подложка строки. Признак
  берётся из `is_head`, то есть по полному имени ссылки, а не по oid: две ветки
  на одном коммите не должны обе получить галку.
- **Стрелки** — справа, `70↑`, `1↓`, при расхождении обе. Больше 99 показывается
  как `99+`. Без upstream — пусто, а не нули: ноль означает «сверено и совпало».
- **`gone`** — своя пометка, не нули: ветка отслеживает то, чего на сервере уже
  нет.
- **Наведение** даёт `⋮` справа.
- **Подсказка с полным именем** — компонент `Tooltip` из shadcn, а не атрибут
  `title`. Сейчас в сайдбаре нативный `title`: он появляется через секунду, не
  там, где нужно, и не поддаётся оформлению. Имена веток длинные и обрезаются
  почти всегда, так что подсказка здесь — основной способ прочитать имя целиком.

## 5. Взаимодействие

| Жест | Что происходит |
|---|---|
| Одинарный щелчок | Ветка выделяется, граф едет на её коммит |
| Двойной по локальной | `git checkout <ветка>` |
| Двойной по удалённой | DWIM, см. ниже |
| Двойной по папке | Свернуть или развернуть |

Задержка между одинарным и двойным не нужна: выделение мгновенно и безвредно,
оно просто случается первым. Это же поведение у GitKraken — на скриншотах видно,
что после двойного щелчка ветка и выделена, и текущая.

### Двойной щелчок по удалённой ветке

Решение принимается в Rust по уже прочитанным ссылкам, а не угадывается git:

- локальная ветка с коротким именем **есть** → `git checkout <короткое имя>`;
- **нет** → `git checkout -b <короткое имя> --track <remote>/<короткое имя>`.

Короткое имя получается снятием префикса remote, и remote берётся из списка
remotes, а не отрезанием до первого слэша: `origin/builds/facebook-fbsource` даёт
`builds/facebook-fbsource`.

Новая операция закрытого списка: `Operation::CheckoutTracking { upstream, local }`.

**Почему не `git switch <короткое имя>` одной командой.** DWIM отказывается
работать, когда ветку с таким именем содержат два remote, — и отказывается
правильно, но нам это состояние известно заранее из уже прочитанных ссылок.
Решив его у себя, мы получаем внятное сообщение вместо отказа git и не зависим
от `checkout.defaultRemote` в чужом конфиге.

### Отказ при грязном дереве

Показывается тост с кодом ошибки. Ни автостеша, ни `--force`. Стеш рядом кнопкой,
он уже есть.

## 6. Свежесть

`git fetch --all` в фоне, **по умолчанию раз в минуту** — как измерено у
GitKraken, — в настройках, с возможностью выключить.

Дальше работает то, что уже построено: фетч двигает `refs/remotes/**`,
наблюдатель шлёт `repo:changed`, `App` перечитывает репозиторий, чужой коммит
появляется в графе, а стрелка меняет число. Новой цепочки не заводится.

Два правила, без которых фоновая задача вредит:

- **Полоса занята — фетч пропускается.** Очередь операций держит одну полосу на
  репозиторий; без этого фоновая задача встанет поперёк push, начатого человеком.
- **Операция человека отменяет идущий автофетч.** В журналах заказчика есть
  таймаут DNS длиной 1 072 056 мс — почти восемнадцать минут. Без отмены
  приложение на эти восемнадцать минут стало бы неотзывчивым, и виноват был бы
  не сетевой сбой, а мы.

### Что автофетч ломает по дороге

`what_changed` в `src-tauri/src/watcher/mod.rs` считает изменением всё под
`.git`, кроме `*.lock` и `objects/tmp_`. Но `git fetch` пишет `FETCH_HEAD`
**при каждом запуске**, даже когда ничего не приехало.

Значит без правки приложение перечитывало бы всю историю раз в минуту впустую.
На react это 36 мс чтения плюс полный перезаполненный фронтенд — и всё это на
пустом месте, шестьдесят раз в час.

`FETCH_HEAD` и `.git/logs/` становятся шумом наравне с `*.lock`. Проверяется
тестом рядом с существующими в `watcher/mod.rs`.

## 7. Чем проверяется

**Отслеживание — фикстурами настоящего git**, как весь слой чтения: ветка
впереди, позади, разошедшаяся, без upstream, с исчезнувшим upstream, ветка с
одинаковым именем в двух remote. Числа сверяются с `git rev-list --left-right
--count`, то есть с независимым от `for-each-ref` ответом самого git.

**Дерево** — тестами `src/refTree.ts` без React.

**Аргументы операций** — тестами рядом с существующими в `operations.rs`:
существующая локальная ветка не получает `-b`, отсутствующая получает `--track`,
ни один путь не содержит `--force`.

**Шум наблюдателя** — тест, что `FETCH_HEAD` не считается изменением, а
`refs/remotes/origin/main` считается.

## 8. Чего не делаем

**Глазик — фильтр графа по одной ветке.** Он есть на скриншотах заказчика, но
решение принято: не сейчас. Это правка чтения и раскладки, а не сайдбара.

**Содержимое меню `⋮`.** Кнопка рисуется, наполнение — отдельной работой.

**Пул при переключении.** Разобрано выше: GitKraken этого не делает, и делать
это опасно — merge или rebase запускались бы двойным щелчком.
