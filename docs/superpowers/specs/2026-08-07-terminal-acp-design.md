# Терминал и агентские сессии

**Дата:** 2026-08-07
**Статус:** принято
**Основание:** пять кликабельных мокапов на токенах приложения
(`.superpowers/brainstorm/25280-1786098871/`), спайк стека в настоящем окне
Tauri с замерами, проверка экосистемы ACP по состоянию на август 2026.

## 1. Замысел

gitspy становится инструментом вайбкодинга: рядом с графом и диффами живут
терминалы и сессии AI-агентов. Архитектура делится на два слоя по признаку
гарантий, а не по видимости:

| Слой | Что это | На чём стоит |
|---|---|---|
| Терминал | Обычный отличный терминал: PTY, байты, табы | Ни на чём агентском: он не знает, что внутри запущен агент |
| Агентские сессии | Ленты сессий с разрешениями, планами, чекпоинтами | Только ACP — типизированный протокол, никаких эвристик по выводу |

Правило, замыкающее дизайн: **агентская фича либо стоит на протоколе, либо
не делается.** Угадывание статуса агента по OSC-последовательностям, чипы
как сахар над слэш-командами, парсинг вывода — рассматривались, промокаплены
и отброшены: всё это эвристики, которые молчаливо врут при обновлении агента.
ACP даёт те же фичи как поля протокола.

## 2. Принятые решения

### Раскладка

Центр репо-вкладки — стопка видов: граф / диф / файл сменяют друг друга.
Терминалы — отдельная зона: нижний док (по умолчанию) или колонка справа
(режим «рядом»). Обе зоны видны одновременно — ключевой сценарий «ревьюю
диф, внизу работает агент». Пропорция меняется одним действием (свап),
док сворачивается в полоску и разворачивается на весь центр.

### Обзор сессий

Вертикальный список справа от терминала, как в VS Code: иконка, живой
заголовок, точка статуса команды. Заголовок задаёт сама программа через
OSC 0/2 — Claude Code пишет туда свою текущую задачу, поэтому список
сессий читается как дашборд «кто чем занят» без единой агентской фичи
с нашей стороны.

### Терминал (v1)

- PTY со **живым** окружением: логин-шелл пользователя, его PATH и конфиги,
  cwd по репозиторию или worktree. Это противоположность `gitspy-exec`,
  где окружение намеренно обезврежено; поэтому отдельный крейт
  `crates/gitspy-term`, а не расширение exec.
- Кликабельные ссылки: URL — в браузер; путь файла (включая `file:12:5`) —
  диф или файл в центре; хеш коммита — подсветка коммита в графе.
  Реализация — свой `ILinkProvider` xterm.js плюс штатный аддон для URL.
- Shell integration: свой сниппет для zsh с OSC 133 — границы команд,
  статус упавшей команды, прыжки между командами; OSC 7 — трекинг cwd.
- Сплит-кнопка «+»: клик — новый zsh, стрелка — профили. Профиль — это
  просто сохранённая команда запуска (`zsh`, `claude`, `codex`,
  `npm run app`), без какой-либо агентской обвязки.
- Поиск по скроллбэку, снятие и восстановление экрана при переключении
  табов (`addon-serialize`), OSC 52 для буфера.
- Цвета ANSI и всё оформление — из токенов `src/index.css` через
  `getComputedStyle`, как это уже делает canvas графа.

### Агентские сессии (v2, только ACP)

Сессия — лента, а не терминал: сообщения, карточки инструментов, план,
вложенные стенограммы субагентов, запросы разрешений, поле ввода.

- **Адаптеры.** Клиентская сторона ACP — мы. Агенты подключаются командой
  запуска: `claude-agent-acp` (обёртка официального Claude Agent SDK,
  поддерживается организацией ACP), `codex-acp` (Rust-адаптер там же),
  Gemini CLI — нативно. Профиль ACP-сессии — та же строка команды, что
  и у терминального профиля.
- **Терминалы агента — наши.** По ACP команды агента выполняет клиент:
  `Bash(...)` агента крутится во встроенном xterm внутри карточки. Слой
  терминала v1 — обязательный фундамент ACP, а не параллельная фича.
- **Разрешения.** Запрос — структурное событие → карточка с кнопками
  разрешить / всегда для этого класса / отклонить. Правила «всегда»
  сохраняются. Отвечать можно из списка сессий и из системного
  уведомления, не покидая текущий вид.
- **Чекпоинты.** Правки агента приходят через `fs/write` клиента — перед
  каждой записью снапшот рабочего дерева в `refs/gitspy/checkpoints`
  (вне обычного графа), в ленте — маркер с откатом одной кнопкой. Это
  страховка git-уровня поверх любого агента.
- **Чипы модели и режима** в шапке сессии — протокольные поля ACP
  (model config, session modes), не слэш-команды.
- **Статусы** ждёт/работает/готов — из протокола; уведомление «агент
  ждёт» — системное.
- **Из дифа — агенту.** Кнопка на ханке кладёт `@путь:строки` в поле
  ввода выбранной сессии.
- **PTY-путь остаётся навсегда.** Агент запускается в обычном терминале
  как любая программа — свежие фичи CLI доступны в день выхода, пока
  адаптер догоняет. Это осознанный запасной выход, а не временный.

## 3. Стек и замеры

Спайк в настоящем окне Tauri (`VITE_SPIKE=term`, второй экземпляр на
отдельном порту), все проверки автоматические, числа из stdout:

| Проверка | Результат |
|---|---|
| PTY: `test -t 1` в zsh `-il`, cwd репозитория | TTY настоящий |
| `Channel` + `InvokeResponseBody::Raw` | байты доезжают как ArrayBuffer |
| WebGL-рендер xterm.js в WKWebView | поднялся |
| OSC 0/2 → `onTitleChange` | долетает |
| resize → `stty size` | ровно 30x120 |
| `cat` 10 МБ сквозь весь тракт | 1100 мс ≈ 9.3 МБ/с, xterm разгребает с нулевым отставанием |
| кадры под потоком | одна дыра 376 мс за залп |

Выбор:

| Слой | Библиотека | Примечание |
|---|---|---|
| Эмулятор | `@xterm/xterm` + `addon-webgl`, `fit`, `search`, `serialize`, `clipboard`, `unicode11` | движок терминала VS Code; свой эмулятор — не наша война |
| Ссылки | свой `ILinkProvider` + `addon-web-links` | пути и хеши — наша логика |
| OSC | `registerOscHandler` | 133 / 7 / 0-2 |
| PTY | `portable-pty` 0.9 | крейт WezTerm |
| Транспорт | Tauri `Channel`, сырые байты | вывод копится и отдаётся раз в кадр; ack-флоу-контроль как у VS Code — это же закрывает дыру 376 мс |
| ACP (v2) | крейт `agent-client-protocol` | JSON-RPC по stdio из `src-tauri`, спавн адаптера на сессию |

Zed как источник: не терминал (их скорость — из нативного GPUI, у нас
webview, перенос не работает), а `alacritty_terminal` как кандидат для
брокера персистентности в v3 и сам ACP.

## 4. Границы

- `crates/gitspy-term` — PTY, сессии, живое окружение. Не знает про Tauri.
- `src-tauri` — команды `term_*`, каналы; в v2 `acp_*` и типы событий
  через `#[derive(TS)]` в `src/generated/`.
- Фронт по FSD: `entities/terminal` (обёртка xterm, модель сессии),
  `features/terminal` (профили, список сессий, ссылки),
  `widgets/TerminalDock`. В v2 — `entities/agent`, `features/agent`,
  лента как часть дока.
- Тексты — ключи i18n, ошибки — код и параметры, как везде.

## 5. Фазы и готовность

**v1 — терминал.** Готовность: док открывается, zsh живой; `cat` 10 МБ
без фризов с числом в замере; клик по хешу подсвечивает коммит в графе,
клик по пути открывает диф; заголовок таба меняется программой изнутри;
профиль запускает `claude` как обычную программу; свап и сворачивание
работают; при переключении табов экран сессии восстанавливается.

**v2 — ACP.** Готовность: сессия через `claude-agent-acp` доходит до
запроса разрешения и продолжается после ответа карточкой; правка агента
оставляет чекпоинт, откат восстанавливает дерево; `Bash` агента виден
во встроенном xterm; ханк из дифа попадает в поле ввода; правило
«всегда разрешать» переживает перезапуск.

**v3.** Worktree-цикл (создать сессию в дереве → принять merge'ем или
выбросить), персистентность (ACP `session/resume` + брокер, кандидат
`alacritty_terminal`), мультирепо-сводка сессий на стартовой странице,
палитра команд.

## 6. Не делаем

IDE-функции (LSP-редактор, отладчик); свой чат поверх PTY-вывода; парсинг
вывода агентов; агентские чипы и статусы в PTY-режиме (умерло вместе с
идеей «умного терминала» — см. раздел 1); персистентность сессий в v1;
удалённые ACP-агенты, пока протокол не стабилизировал транспорт.

## 7. В план реализации

Батчинг вывода по кадрам и ack-флоу-контроль с замером до/после; закрытие
CSP (спайк показал, что внешних ресурсов терминалу не нужно); судьба
спайк-файлов (`spike_term.rs`, `src/spike/`) — переработка в `gitspy-term`
первым шагом; сниппет shell integration для zsh; дизайн от дизайнера
поверх мокапов (бриф передан, чипы из него уезжают в ACP-ленту).
