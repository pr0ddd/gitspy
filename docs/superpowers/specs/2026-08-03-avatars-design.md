# Аватарки: почта как ключ, провайдеры как источники

Дата: 2026-08-03. Требование: несколько провайдеров (GitHub сейчас, GitLab и
Bitbucket потом) без переделки основания.

## 1. Главное решение: ключ — почта коммита

Аватарка принадлежит не логину на хосте, а автору коммита, и единственное, что
есть у каждого коммита на любом хосте, — почта. Поэтому вся система — это одно
отображение `почта → картинка на диске`, а провайдеры лишь заполняют его.
Логины, id пользователей и прочие сущности хостов наружу слоя провайдера не
выходят.

## 2. Три источника, от дешёвого к дорогому

| Источник | Цена | Что даёт |
|---|---|---|
| разбор служебной почты | ноль сети, ноль токена | `12345+login@users.noreply.github.com` → адрес картинки арифметикой |
| API провайдера, пакетно | сеть, токен | почты остальных авторов через историю коммитов хоста |
| идентикон | ноль всего | детерминированная картинка из почты — уже есть в render |

Разбор служебных почт — чистая функция на таблице провайдеров: у GitHub форма
`id+login@users.noreply.github.com` и старая `login@users.noreply.github.com`,
у GitLab — `id-login@users.noreply.gitlab.com`. Добавить провайдера — строка в
таблице и тесты, не архитектура.

## 3. Слои

| Где | Что |
|---|---|
| `gitspy-hosts` | `avatars.rs`: разбор служебных почт (таблица провайдеров); у `GitHub` возвращается пакетный метод почта→URL через историю коммитов — тот, что был удалён как мёртвый, теперь с вызывающим |
| `src-tauri/src/avatars.rs` | хранилище: `avatars/{sha256(почта)}.img` + `avatars/index.json` (почта → файл, время); команда `avatar_paths(repo)`; фоновая задача докачки |
| `src` | `AvatarCache` во фронтенде: почта → `HTMLImageElement` через `convertFileSrc`; `render.ts` рисует картинку, если она загружена, иначе идентикон — без ожиданий в кадре |

## 4. Когда ходим в сеть

Открытие репозитория рисует граф сразу и читает только диск: `avatar_paths`
отдаёт готовые файлы. Докачка — фоновая задача, стартующая сама после того,
как репозиторий открыт и отрисован (решение 2026-08-03: привязка докачки к
кнопке fetch была ошибкой — фон не мешает открытию). Индекс пишется после
каждой картинки, чтобы прерывание не теряло прогресс. Задача берёт почты видимой истории,
вычитает уже известные, служебные решает локально, остальные — пакетным
методом провайдера; картинки кладёт на диск и шлёт `avatars:changed`, фронтенд
перечитывает пути. Повторные отказы почты помечаются в индексе, чтобы не
спрашивать хост об одном и том же каждый раз.

## 5. Готовность

- Открытие репозитория не делает сетевых вызовов; аватарки из кэша видны сразу.
- Служебные почты дают картинку без токена вовсе.
- Автор без аватарки везде рисуется одним и тем же идентиконом.
- Отключение аккаунта чистит скачанное этим аккаунтом (правило приватности
  фазы 8).
