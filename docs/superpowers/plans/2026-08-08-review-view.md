# Вид ревью: все изменения одним свитком — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** В полноэкранном режиме сегмент «Изменения» показывает не список файлов и отдельный дифф, а один свиток: файлы с числами, каждый разворачивается на месте, между ханками — раскрывающиеся «N unmodified lines».

**Architecture:** Данные уже есть — `workingTreeHunks` отдаёт `UnifiedDiff` с ханками, `hiddenSpans` считает свёрнутые промежутки. Новый виджет `ReviewView` показывает список файлов рабочего дерева и подгружает ханки лениво, по раскрытию файла. Ничего нового у границы не появляется.

**Referenс:** вид ревью Claude Code — шапка `master → working tree`, подпись «Files are collapsed for large diffs. Select a file to expand it.», строка файла с `+114 −3`, внутри — ханки с номерами строк по обеим сторонам и раскрывашки контекста.

## Global Constraints

- **Коммитов и пушей нет.** `git checkout`/`restore`/`stash` по рабочему дереву запрещены полностью: дерево частично не закоммичено, откат сотрёт чужую работу; свою неудачную правку отменяй обратной правкой.
- **Комментариев в коде нет.** Идентификаторы английские, `assert`-сообщения русские.
- **Никаких своих стилей контролов.** Только компоненты из `src/components/ui`, части из `src/parts.tsx` и токены темы. Своя рамка вокруг чужого компонента, `bg-*` мимо токенов, произвольные значения — запрещены; за это уже прилетало.
- Строки UI — ключи i18n; `invoke` — только `src/ipc.ts`; FSD строго вниз.
- TDD: тест падает до реализации. Ворота: `npx tsc --noEmit`, `npx vitest run`, `npm run lint`, `npm run i18n:check`, `cargo test`.
- У пользователя запущено приложение и dev-сервер на 5173 — его процессы не трогать.

### Task 1: Модель свитка — какие строки видны и что свёрнуто

**Files:** `src/entities/diff/review.ts` (создать) + `review.test.ts`, `src/entities/diff/index.ts`

**Interfaces:**
- `type ReviewLine = { kind: 'context' | 'added' | 'removed'; before: number | null; after: number | null; text: string }`
- `type ReviewGap = { kind: 'gap'; hidden: number; from: number; to: number }`
- `type ReviewPiece = ReviewLine | ReviewGap`
- `reviewPieces(diff: UnifiedDiff, opened: { from: number; to: number }[]): ReviewPiece[]` — разбирает ханки в строки с номерами по обеим сторонам, между соседними ханками ставит `gap` с числом скрытых строк; промежутки из `opened` раскрываются в строки контекста, если они есть в дифе, иначе остаются `gap`.
- `expandedAround(gap: ReviewGap, step: number): { from: number; to: number }` — раскрытие на `step` строк от края (для стрелок вверх/вниз у разделителя).

- [ ] **Step 1: Падающие тесты.** На готовом `UnifiedDiff` из фикстуры: номера строк идут по обеим сторонам и не сбиваются на добавленных и удалённых; между двумя ханками появляется ровно один `gap` с верным числом скрытых строк; раскрытие промежутка убирает `gap`; ханк, начинающийся с первой строки файла, не порождает `gap` перед собой.
- [ ] **Step 2: Прогнать — падают.** **Step 3: Реализация.** **Step 4:** тесты и tsc.

### Task 2: Виджет свитка

**Files:** `src/widgets/ReviewView.tsx` (создать) + `ReviewView.test.tsx`, `src/locales/en/common.json`

**Interfaces:**
- `<ReviewView repo={string} tree={WorkingTreeView} onOpenFile={(path: string) => void} />`
- Шапка: `ветка → working tree` и подпись из i18n про свёрнутые файлы.
- Строка файла: `FilePath` из `src/parts.tsx`, справа `+N −M` цветами `text-added`/`text-deleted`, слева шеврон. Клик разворачивает файл и подгружает ханки через `ipc.workingTreeHunks` (по одному запросу на файл, повторно не запрашивать).
- Внутри файла — строки из `reviewPieces`: номера в две колонки `tabular-nums`, знак, текст моноширинным; фон добавленных `bg-added/10`, удалённых `bg-deleted/10` — те же токены, что в существующем `DiffView`.
- Разделитель `gap`: строка с числом скрытых строк и кнопками раскрытия вверх/вниз.
- Пока ханки грузятся — строка ожидания из `InlineNote`, ошибка — `notifyError`.

- [ ] **Step 1: Падающие тесты** с моком `@/ipc`: свёрнутый файл ханков не запрашивает; раскрытие запрашивает ровно один раз и показывает строки; второе раскрытие того же файла нового запроса не делает; `gap` показывает число скрытых строк и раскрывается по кнопке; цифры `+N −M` берутся из дерева, а не считаются заново.
- [ ] **Step 2: Прогнать — падают.** **Step 3: Реализация.** **Step 4:** ворота фронта.
