# Пулл-реквесты: план работ

> Спека: `docs/superpowers/specs/2026-08-03-pull-requests-design.md`.

**Цель:** секция PR в сайдбаре из дискового кэша, карточка с маркдауном и
комментариями, переход на ветку PR одним нажатием.

**Порядок — снизу вверх:** чистый разбор в крейте → команды и кэш → операция
перехода → интерфейс. Каждая задача проверяема сама по себе.

---

### Задача 1. `gitspy-hosts`: owner/repo из адреса remote

- [x] Тесты: три формы адреса GitHub дают owner/repo; GitLab и произвольный
  https дают `None`; `.git` на конце необязателен
- [x] `remote.rs`: `github_repo(url: &str) -> Option<(String, String)>`
- [x] Выбор remote: `origin` с GitHub, иначе первый с GitHub — чистая функция
  над списком пар (имя, адрес), тест на порядок предпочтения

### Задача 2. `gitspy-hosts`: разбор PR

- [x] Тесты на `parse_pulls`: номер, заголовок, draft, автор с аватаркой,
  head/base с признаком форка, updated_at; пустой список; сломанный json
- [x] Тесты на `parse_pull_detail`: тело-маркдаун, метки, ревьюеры, assignees
- [x] Тесты на `parse_comments`: автор, тело, время; пагинация склейкой
- [x] `pulls.rs`: типы + разбор + методы `GitHub::pulls/pull_detail/comments`
  (сеть отдельно от разбора, как в остальном крейте)
- [x] Группировка: `assign_groups(pulls, my_login)` — мои / назначенные /
  ждут ревью / все; тест: PR попадает во все подходящие группы

### Задача 3. Команды и дисковый кэш

- [x] `hosts/storage`: чтение и запись `pulls/github/{owner}--{repo}.json`
  с временем; тест: соседние репозитории не делят файл
- [x] Команда `pull_requests(repo, refresh)`: без refresh — кэш, иначе сеть
  и перезапись; `host.notGitHub`, если remote не нашёлся
- [x] Команда `pull_detail(repo, number)`: всегда сеть, `pull.gone` на 404
- [x] Виды `PullView`, `PullDetailView`, `CommentView` через ts-rs

### Задача 4. Переход на ветку

- [x] Тесты аргументов: `FetchPull { number }` даёт
  `fetch origin +pull/N/head:refs/heads/pr/N`; checkout ветки репозитория
  не создаёт `pr/N`
- [x] `checkout_pull(repo, number, head)`: две команды под одной полосой,
  вторая не идёт после провала первой
- [ ] Интеграционный тест против настоящего git: fetch из локального
  «origin» + checkout, занятая ветка переключается, а не падает

### Задача 5. Интерфейс

- [x] Центральное вью — перечисление `graph | diff | pull` вместо двух флагов
- [x] Секция в сайдбаре: четыре группы со счётчиками, кнопка обновления,
  подпись усечения после 500
- [x] Карточка: заголовок, `head → base`, описание маркдауном
  (`react-markdown` + `remark-gfm`), метки, ревьюеры, комментарии,
  правая рейка с кнопкой «перейти на ветку»
- [ ] Пустые и честные состояния: не GitHub; нет открытых PR; аккаунт не
  подключён (кнопка в настройки)
- [x] Ключи i18n в оба языка; git-словарь не переводится

### Задача 6. Проверки

- [x] `cargo clippy -D warnings`, `cargo test`, `npm run build`
- [ ] Живьём на `react`: 400+ PR, группы, карточка, переход на ветку форка
- [ ] Открытие репозитория с кэшем — ноль сетевых вызовов (лог сети пуст)
