### Задача 1. Дифф: режимы просмотра

**Дефект.** `useEffect` пересоздаёт `IStandaloneDiffEditor` на смену `inline`,
а эффект, который ставит модель, зависит от `repo/target/path` и повторно не
срабатывает. Новый редактор остаётся без модели — «В строку» показывает пустоту.

**Файлы:** `src/shell/DiffView.tsx`

- [x] **Шаг 1: тест на переключение режима**

Чистая часть выносится в `src/diff.ts`:

```ts
export const editorOptionsFor = (mode: DiffMode) => ({
  renderSideBySide: mode === 'split',
  renderMarginRevertIcon: false,
});
```

```ts
it('смена режима меняет опции, а не пересоздаёт редактор', () => {
  expect(editorOptionsFor('split').renderSideBySide).toBe(true);
  expect(editorOptionsFor('inline').renderSideBySide).toBe(false);
});
```

- [x] **Шаг 2: редактор создаётся один раз**

`useEffect` без `inline` в зависимостях; смена режима — `updateOptions`.

- [x] **Шаг 3: три режима вместо двух**

`hunk` — `hideUnchangedRegions: { enabled: true }`, ровно то, что в GitKraken
называется Hunk View: показаны только изменённые куски с контекстом.
Названия — `Hunk view`, `Split view`, `Inline view`, без перевода: это термины.

- [x] **Шаг 4: переключатель уезжает вправо**

Порядок в шапке: статус и путь слева, режимы и закрытие справа.

- [x] **Шаг 5: панель действий диффа**

Навигация по изменениям (`Previous change`, `Next change` — у Monaco есть
`goToDiff`), переключатель пробелов (`ignoreTrimWhitespace`), перенос строк
(`wordWrap`), кодировка в подписи.

- [x] **Шаг 6: File View рядом с Diff View**

Показ файла целиком без сравнения — то же содержимое в обычном редакторе.

- [ ] **Шаг 7: проверка**

### Задача 2. Правая панель выводится из выделения

**Не то спроектировано.** Вкладок быть не должно: панель показывает то, что
выделено. Выделен коммит — подробности коммита. Выделена верхняя строка —
рабочее дерево. Сейчас вкладки позволяют смотреть коммит, стоя на рабочем
дереве, и наоборот — состояние, которого в приложении не существует.

**Файлы:** `src/App.tsx`, `src/shell/Details.tsx`

- [x] **Шаг 1: снять вкладки и `showTree`**

Панель выбирается по `rows.row(selected).kind`.

- [x] **Шаг 2: плашка перехода**

В подробностях коммита сверху — строка «N изменений в рабочем дереве» с
кнопкой, которая выделяет верхнюю строку. Это единственный переход, и он
явный.

- [x] **Шаг 3: описание по содержимому**

Убрать `basis-1/2`: блок описания растёт по тексту до потолка, дальше
прокручивается сам. Список файлов занимает остаток.

- [x] **Шаг 4: тест на выбор панели**

```ts
it('панель следует за выделением, а не за вкладкой', () => {
  expect(panelFor({ kind: 'workingTree' })).toBe('workingTree');
  expect(panelFor({ kind: 'commit' })).toBe('commit');
});
```

fn a_repository_read_once_is_not_read_again_until_git_changes() {

### Задача 10. Ресайз колонок

**Требует проекта, а не кода.** Пограничные состояния, которые надо решить до
реализации:

- минимальная ширина колонки и что происходит при попытке уйти под неё;
- колонка графа: она не текстовая, её ширина следует за числом дорожек;
- сохранение ширин — на репозиторий или на приложение;
- поведение при изменении размера окна: пропорция или фиксированные пиксели;
- перетаскивание границы при горизонтальной прокрутке графа;
- сброс к значениям по умолчанию.

Сейчас геометрия колонок **вычисляется** из ширины окна (`scene.ts`).
Ресайз означает переход к **хранимой** геометрии, и это меняет источник правды
для отрисовки, попадания клика и положения поля ввода. Делать это между делом
нельзя — сначала спека.

- [x] **Шаг 1: спека на хранимую геометрию колонок**

`docs/superpowers/specs/2026-08-03-column-geometry-design.md`

- [x] **Шаг 2: `layoutColumns` — один источник для отрисовки, клика и поля ввода**

`src/columns.ts`; `scene.ts`, `render.ts` и `GraphView` переведены, старые
функции колонок удалены.

- [x] **Шаг 3: перетаскивание, сброс двойным щелчком, `localStorage`**

- [x] **Шаг 4: пересмотр после первой пробы**

Первая версия делала поглотителем граф — он прыгал на каждом ресайзе, а колонки
правого блока растягивались в другую сторону. Причины и решения записаны в
спеке (раздел «Пересмотр»): поглотитель — сообщение; каждую колонку правого
блока тянет её левая граница; дорожки заякорены к левому краю графа, ворота
прижатия больше не сдвигают координаты. Тест держит главное свойство: граница
ходит ровно за курсором по каждой из пяти границ, а граф не шевелится, когда
тянут чужую.
